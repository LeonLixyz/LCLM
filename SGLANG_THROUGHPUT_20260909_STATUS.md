# Qwen3.8-27B serving smoke

This bounded serving experiment replays exactly 128 already captured first-turn requests from the failed-task pilot. It creates no rollout continuations or training rows. The source selection is the first 128 completed pilot tasks, so completion-order/source bias applies. Its request latency cannot be compared to the original pilot's whole-task latency; only absolute request/token throughput is reported unless a separate matched baseline is run.

The model, revision, BF16 precision, container digest, nonthinking request settings, tool parser, and reasoning parser match the pilot. The layout changes to eight independent TP1 servers in one H200:8 container, each with CUDA graphs enabled, maximum batch/concurrency 16, Mamba cache size 80, and 32K context. Host allocation is 32 CPUs and 256 GiB memory. Server 0 first boots and executes one of the 128 frozen requests; then the other seven boot and the remaining 127 run as a single wave. Every server must show actual graph-capture log evidence. There is a one-hour function cap and no automatic retry.
