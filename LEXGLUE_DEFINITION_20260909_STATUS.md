The separate LexGLUE task-definition correction is ready for an explicitly versioned new snapshot. It has not changed any live input, result, verifier, generation app, or packing selection. The original opaque-prompt probe remains diagnostic evidence about its original task definition.

`data/lexglue_task_definition_correction.py` exposes `amend_lexglue_task(task, *, definitions_path=DEFINITIONS_PATH)`. It returns a copy, preserves task IDs, source IDs, gold fields, support IDs, source segments, tools and attempt provenance, and changes the shared question plus the stored training/user/rollout prompts together. Its `corrected_question(config, question)` helper takes no gold or evidence argument. It verifies the original complete label list rather than guessing how to rewrite a modified question. CaseHOLD is returned unchanged. Existing `prepare_teacher_task` may run before or after the correction; both orders produce identical prepared tasks for all six amended configs.

The explicit version is `lexglue-upstream-ontology-20260909-v1`. Amended tasks carry `task_definition_correction` with the original question, original/corrected question hashes, config and frozen definition hash. Task IDs are preserved for lineage; the containing new input manifest must bind the new task bytes and distinguish this task version. The original input files remain the authoritative original snapshot. No old result can be represented as generated from a corrected prompt.

The definitions are supported by primary upstream materials:

- The [LexGLUE dataset card and feature metadata](https://huggingface.co/datasets/coastalcph/lex_glue/blob/c23fdff1a6bf74e0e1a71cb86f1e781d37da888c/README.md), pinned at `c23fdff1a6bf74e0e1a71cb86f1e781d37da888c`, supply actual label IDs/order and task objectives. SCOTUS has exactly 13 labels in these features; the card's prose mentioning a 14th issue area does not justify introducing an absent output label.
- The card directly links the [MultiEURLEX descriptor mapping](https://github.com/nlpaueb/multi-eurlex/blob/078092d62633ab1fc85065cc5937e60edd805095/data/eurovoc_descriptors.json). All 100 EURLEX label IDs are joined by their exact dictionary keys to English meanings, not matched by guessed names. All 100 also match the ordered list in the benchmark author's [zero-shot instruction builder](https://github.com/coastalcph/zeroshot_lexglue/blob/d23e81e4a0c59518c0c102357bdeaf4ba0db82f4/build_instructions/eurlex_instructions.py).
- The same author's [SCOTUS instruction builder](https://github.com/coastalcph/zeroshot_lexglue/blob/d23e81e4a0c59518c0c102357bdeaf4ba0db82f4/build_instructions/scotus_instructions.py) supplies the 13 ordered issue-area meanings. SCOTUS and LEDGAR now request one issue-area code or one main-topic section title, respectively.
- The [European Convention text](https://www.echr.coe.int/documents/d/echr/convention_eng) verifies the ten retained article meanings. ECHR-A predicts violations found; ECHR-B identifies alleged violations considered by the Court. A and B therefore have separate task objectives despite sharing article labels.
- The original [CLAUDETTE annotation paper, version 2](https://arxiv.org/html/1805.01217v2), sections 2 and 3.1, supports the eight UNFAIR-ToS categories and their fairness distinction. The correction asks about actual potentially unfair stipulations and their exceptions, rather than treating any mention of a category as sufficient. That instruction is a gold-independent paraphrase of the annotation scheme, not a new per-example adjudication. Fair exceptions and fully optional arbitration can be negative; blanket legal-maximum qualifiers alone do not make a liability exclusion fair.
